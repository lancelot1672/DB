# TIBERO SQL Grid — 조회 SQL 저장 기능 계획서

> 대상: `TIBERO/app.py` (Streamlit · PostgreSQL 9.6 조회 전용 그리드)
> 상태: **구현 완료** (1~3단계 전부). 아래 계획 대비 변경점은 §10 참고.
> 관련 문서: `TIBERO/SQL_GRID_WEB_PLAN.md` §8 "범위 외 — 쿼리 저장/즐겨찾기" 를 정식 범위로 승격한다.

---

## 1. 목적 / 배경

현재 앱은 SQL 을 텍스트 영역에 붙여넣어 실행하는 구조이고, 재사용 가능한 쿼리는
코드에 하드코딩된 `PRESETS` 딕셔너리(`app.py:234`)뿐이다. 월간 점검처럼 **같은 쿼리를
반복 수행**하는 용도이므로, 사용자가 화면에서 직접 쿼리에 이름을 붙여 저장하고
다음 접속 때 불러 쓸 수 있어야 한다.

해결할 문제:
- 자주 쓰는 점검 쿼리를 매번 외부 편집기/메모장에서 복사해 붙여넣어야 함
- 쿼리를 추가하려면 `app.py` 를 수정하고 재배포해야 함 (폐쇄망 환경에서 부담)
- 앱 재시작 / 브라우저 새로고침 시 작성 중이던 쿼리가 사라짐

## 2. 범위

### 포함 (In Scope)
- 편집기의 현재 SQL 을 **이름을 붙여 저장**
- 저장된 쿼리 **목록 조회 / 불러오기 / 덮어쓰기 / 이름 변경 / 삭제**
- 저장 데이터의 **파일 영속화**(앱 재시작 후에도 유지)
- 저장 목록 **JSON 내보내기 / 가져오기**(서버 이관·백업용)
- 현재 SQL 을 `.sql` 파일로 다운로드

### 제외 (Out of Scope)
- 저장소로 DB 테이블 사용 — 앱은 `conn.set_session(readonly=True)` 읽기 전용 세션 + 읽기 전용
  계정을 전제로 하므로 **DB 에 쓰기를 할 수 없다**. 이 가드를 깨는 선택지는 검토 대상에서 제외한다.
- 사용자별 소유권 / 권한 분리 (앱에 로그인 개념이 없음 — 사내망 단일 사용자 전제)
- 쿼리 버전 이력, 변경 diff, 공유 링크
- 쿼리 실행 결과의 저장 (결과는 기존 CSV 다운로드로 충분)
- 파라미터 바인딩(`:from_date` 같은 치환 변수) — 3단계에서 별도 판단

## 3. 설계 결정

### 3.1 저장 위치 — 단일 JSON 파일

| 후보 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 단일 JSON 파일 | 원자적 교체 쉬움, 내보내기/가져오기가 파일 복사, 목록 로딩 1회 | 파일 전체 재작성 | ✅ |
| 쿼리당 `.sql` 파일 | 외부 편집기로 직접 수정 가능 | 이름↔파일명 매핑/인코딩/메타데이터 관리 부담 | ✖ |
| SQLite | 동시성 안전 | 의존성 추가, 폐쇄망 wheel 반입 대상 증가, 파일 반출 불편 | ✖ |
| DB 테이블 | 서버 간 공유 | **읽기 전용 세션 가드와 충돌** | ✖ |

**경로**: `TIBERO/queries/saved_queries.json`
- `PG.env` 와 동일한 방식으로 `SQLGRID_QUERY_FILE` 환경 변수로 덮어쓸 수 있게 한다
  (`app.py:37` 의 `SQLGRID_ENV_FILE` 패턴 그대로). `run.py` 에 `--queries <path>` 옵션 추가.
- 이렇게 두면 재배포(`package.sh` tar 해제)로 앱 디렉터리를 갈아엎어도, 저장 파일을
  `/var/lib/sqlgrid/saved_queries.json` 같은 앱 바깥 경로로 지정해 보존할 수 있다.

### 3.2 데이터 스키마

```json
{
  "version": 1,
  "updated_at": "2026-08-10T14:03:11",
  "items": [
    {
      "id": "q_20260810_140311_a1b2",
      "name": "테이블별 건수 점검",
      "sql": "SELECT ...",
      "note": "월간 점검 1번 항목",
      "created_at": "2026-08-10T14:03:11",
      "updated_at": "2026-08-10T14:03:11"
    }
  ]
}
```

- `id` 는 불변 키(이름 변경 시에도 유지). `name` 은 표시·검색용이며 **중복 불가**.
- `version` 은 스키마 변경 대비. 로드 시 모르는 버전이면 읽기 전용으로 취급하고 경고.
- 날짜는 `datetime.now().isoformat(timespec="seconds")` (앱이 이미 로컬 시각 기준으로 로깅함).

### 3.3 조회 전용 가드 유지 (★ 반드시)

`CLAUDE.md` 에 명시된 필수 보존 사항이다. 저장 기능은 이 가드를 **우회하는 경로가 되면 안 된다**.

- **저장 시점에도** `validate_sql()` 을 통과한 SQL 만 저장한다.
  → 저장소가 DML/DDL 텍스트의 보관함이 되지 않게 하고, "불러오기 → 실행" 경로가 항상 안전하다.
- **불러오기 시점에도** 실행 직전 기존 `validate_sql()` 이 다시 돌므로 이중 방어가 된다
  (파일을 손으로 편집해 DML 을 넣어도 실행은 차단됨).
- **가져오기(JSON 업로드)** 시 항목별로 `validate_sql()` 을 돌려 실패 항목은 건너뛰고 사유를 표시한다.
- 저장 파일 경로는 앱이 정한 경로만 사용한다. 사용자가 화면에서 임의 경로를 입력해
  파일을 쓰는 UI 는 만들지 않는다(경로 탈출 방지).

### 3.4 안전한 파일 쓰기

- 같은 디렉터리에 `saved_queries.json.tmp.<pid>` 로 쓰고 `os.replace()` 로 원자 교체
  (레포 공통 규약의 "tmp 에 PID 접미사로 작성 후 정리" 와 같은 취지).
- 저장 직전 파일 `mtime` 을 비교해, 로드 이후 외부에서 바뀌었으면 **다시 읽어 병합한 뒤 쓴다**
  (브라우저 탭 2개, 또는 손으로 파일 편집한 경우). 충돌 시 경고 메시지 표시.
- 쓰기 실패(권한·디스크)는 앱을 중단시키지 않고 `st.error` + 로그로 처리한다.

### 3.5 제한값 (방어적 상한)

| 항목 | 값 | 이유 |
|---|---|---|
| 쿼리 개수 | 200 | 목록 UI/파일 크기 |
| 이름 길이 | 60자 | 목록 표시 |
| SQL 길이 | 200,000자 | 요구사항의 "100줄 규모" 대비 충분 |
| 메모 길이 | 200자 | |

이름은 앞뒤 공백 제거 후 제어문자를 걸러낸다. 빈 이름 금지.

## 4. UI 설계

기존 레이아웃(헤더 → 편집기 → 태그/버튼 → 결과)을 유지하고, **좌측 사이드바에 저장 쿼리 패널**을
추가한다. 본문 폭(그리드)을 줄이지 않기 위한 선택이다.

```
┌ Sidebar ───────────────┐  ┌ Main ─────────────────────────────────┐
│ 📁 저장된 쿼리 (12)     │  │ 🗄️ SQL Grid      user@host  READ ONLY │
│ [🔍 이름 검색_______]   │  ├────────────────────────────────────────┤
│ ○ 테이블별 건수 점검     │  │ 샘플 [customers][orders][transactions] │
│ ○ 인덱스 상태           │  │ ┌ SQL 텍스트 영역 ───────────────────┐ │
│ ○ 세션 현황             │  │ │                                    │ │
│ ...                    │  │ └────────────────────────────────────┘ │
│ [불러오기][삭제]        │  │ [SELECT전용][다중문차단] [💾저장][지우기][▶실행] │
│ ─────────────          │  ├────────────────────────────────────────┤
│ ▸ 내보내기 / 가져오기    │  │ 건수 시간 메모리 컬럼      [⬇CSV 저장]  │
└────────────────────────┘  │ ┌ 그리드 ──────────────────────────┐  │
```

### 4.1 저장 (본문 `💾 저장` 버튼)
- 클릭 시 편집기 아래 `st.expander("쿼리 저장", expanded=True)` 안의 폼을 연다
  (`st.popover`/`st.dialog` 는 Streamlit 1.31+ 이므로, `requirements.txt` 의 `streamlit>=1.28` 하한을
  깨지 않도록 **expander + form** 으로 구현한다).
- 폼 구성: 이름(text_input, 선택된 쿼리가 있으면 그 이름을 기본값) · 메모(선택) · [저장] [취소]
- 이름이 이미 있으면 `⚠ 같은 이름이 있습니다. 덮어쓸까요?` 체크박스를 켜야 저장되게 한다
  (레포 공통 규약 5 — 파괴적 작업은 확인 후 수행).
- 저장 전 `validate_sql()` 실패 시 저장하지 않고 사유를 표시.

### 4.2 목록 / 불러오기 (사이드바)
- 이름 검색 입력(부분 일치, 대소문자 무시) → `st.radio` 또는 `st.selectbox` 로 목록 표시.
  검색 결과 0건이면 안내 문구.
- **[불러오기]** — 선택 쿼리의 SQL 을 `st.session_state.sql_input` 에 넣는다.
  ⚠ 구현 주의: 위젯 인스턴스화 이후에는 세션 상태를 수정할 수 없으므로 **반드시 `on_click` 콜백**에서
  대입한다. 기존 `set_preset()`/`clear_sql()`(`app.py:273-278`)과 동일한 패턴을 따른다.
- 불러오기 시 편집기에 미저장 변경이 있으면 캡션으로 알린다(현재 SQL 과 저장본이 다를 때 `● 수정됨` 표시).
- **[삭제]** — `y/N` 대신 `삭제 확인` 체크박스를 켠 뒤에만 활성화. 삭제된 SQL 은 1회에 한해
  세션에 보관해 `되돌리기` 버튼을 노출(선택 구현).
- **이름 변경** — 선택된 항목의 이름을 사이드바 text_input 으로 수정 후 [이름 변경].
- 선택된 항목은 사이드바 하단에 저장 시각 / 줄 수 / 메모를 캡션으로 표시.

### 4.3 내보내기 / 가져오기 (사이드바 expander)
- **내보내기**: `st.download_button` 으로 `saved_queries_YYYYMMDD_HHMMSS.json` 다운로드
  (기존 CSV 다운로드와 동일한 파일명 규칙).
- **가져오기**: `st.file_uploader(type=["json"])` → 스키마 검증 → 병합 모드 선택
  (`이름 충돌 시 건너뛰기` / `덮어쓰기`) → 미리보기(추가 N건, 갱신 M건, 스킵 K건) → [적용] 확인.
- **현재 SQL 을 .sql 로 저장**: 편집기 하단 `⬇ .sql` 다운로드 버튼(저장소를 거치지 않는 단순 반출).

### 4.4 기존 `PRESETS` 와의 관계
- `PRESETS` 는 코드 내장 샘플로 **그대로 둔다**(읽기 전용). 사이드바 목록과 섞지 않는다.
- 샘플 버튼으로 불러온 뒤 저장하면 사용자 쿼리로 편입되는 흐름이 자연스럽다.

### 5.2 `app.py` 추가 구성요소

`app.py` 의 기존 번호 섹션 구조를 유지하고, **§7 PRESETS 뒤에 §7.5 "저장 쿼리 저장소"** 를 끼워 넣는다.

```python
# 상수
QUERY_PATH = os.environ.get("SQLGRID_QUERY_FILE") or os.path.join(BASE_DIR, "queries", "saved_queries.json")
QUERY_SCHEMA_VERSION = 1
MAX_SAVED_QUERIES, MAX_NAME_LEN, MAX_SQL_LEN = 200, 60, 200_000

# 저장소 (순수 함수 — Streamlit 비의존, 테스트 가능)
def load_store() -> dict                      # 파일 없으면 빈 store, 깨졌으면 백업 후 빈 store + 경고
def save_store(store: dict) -> None           # tmp + os.replace 원자 쓰기
def store_mtime() -> float | None
def find_by_name(store, name) -> dict | None
def upsert_query(store, name, sql, note="") -> tuple[dict, str]   # (item, "created"|"updated")
def rename_query(store, qid, new_name) -> None
def delete_query(store, qid) -> dict          # 삭제된 항목 반환(되돌리기용)
def validate_store(obj) -> tuple[bool, str]   # 가져오기 검증
def merge_store(base, incoming, overwrite: bool) -> dict          # 반환 시 통계 포함

# Streamlit 콜백 (위젯 생성 전에 세션 상태를 바꾸기 위해 on_click 에서만 호출)
def cb_load_saved(qid)     # st.session_state.sql_input = item["sql"]
def cb_save_current()
def cb_delete_saved(qid)
def cb_rename_saved(qid)

# 렌더
def render_sidebar_queries(logger)   # 검색 / 목록 / 불러오기 / 이름변경 / 삭제 / 내보내기 / 가져오기
def render_save_form(logger)         # 본문 저장 폼
```

`main()` 변경점:
- 진입부에서 `st.session_state.setdefault("saved_store", load_store())`, `selected_qid`, `show_save_form` 초기화
- 헤더 렌더 직후 `render_sidebar_queries(logger)` 호출
- 버튼 행(`app.py:322-334`)을 `[태그][💾 저장][지우기][▶ 실행]` 로 확장 (컬럼 비율 `[4,1,1,1]`)
- 저장/삭제/이름변경/가져오기 발생 시 기존 `logger` 로 감사 로그 기록:
  `SAVE\t<name>\t<len>`, `DELETE\t<name>`, `RENAME\t<old> -> <new>`, `IMPORT\t+N ~M`

**성능 주의**: `load_store()` 는 매 rerun 마다 호출하지 않는다. 세션 상태에 캐시하고,
쓰기 직전에만 `store_mtime()` 으로 최신 여부를 확인해 필요 시 재로딩한다.

### 5.3 단계 분할

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **1 (MVP)** | 저장소 함수 + 저장/목록/불러오기/삭제, 파일 영속화, 로깅 | 저장 → 앱 재시작 → 불러오기 성공 |
| **2** | 이름 변경, 이름 검색, 중복 덮어쓰기 확인, `● 수정됨` 표시, 되돌리기 | 아래 6장 체크리스트 통과 |
| **3** | JSON 내보내기/가져오기, `.sql` 다운로드, `run.py --queries`, 문서 갱신 | 서버 A→B 이관 시연 |

각 단계는 독립적으로 배포 가능하다. 1단계만 반영해도 기능은 성립한다.

## 6. 테스트 체크리스트 (수동 — 레포에 테스트 스위트 없음)

**정상 경로**
- [ ] 쿼리 저장 → 사이드바 목록에 나타남 → 새로고침(F5) 후에도 유지
- [ ] 앱 완전 재시작(`./run.sh`) 후에도 유지
- [ ] 불러오기 → 편집기에 SQL 이 정확히 들어오고 [▶ 실행] 성공
- [ ] 같은 이름 저장 → 덮어쓰기 확인 후 `updated_at` 만 갱신, `id`/`created_at` 유지
- [ ] 이름 변경 후에도 선택 상태 유지
- [ ] 삭제 → 목록에서 사라지고 파일에서도 제거

**가드 (★)**

## 7. 배포 / 운영 영향

- **폐쇄망**: 새 의존성 없음(`json`, `os` 표준 라이브러리만). `make_wheels.sh` / `requirements.txt` 변경 불필요 — 이번 계획의 중요한 제약 조건이다.
- **백업**: `queries/saved_queries.json` 한 파일만 복사하면 된다. README 에 명시.
- **재배포 시 데이터 보존**: `package.sh` 산출물에는 `queries/` 를 포함하지 않는다. tar 해제 위치가
  기존 앱 디렉터리와 같다면 파일이 그대로 남고, 다르다면 위 파일 1개만 복사하거나
  `--queries` 로 앱 바깥 경로를 가리키게 한다.
- **권한**: 자격증명이 아니므로 `chmod 600` 까지는 불필요(`644` 권장). 다만 파일에 사내 스키마/테이블명이
  담기므로 반출 시 주의 대상임을 README 에 한 줄 남긴다.

## 10. 구현 결과 — 계획 대비 변경점

계획대로 1~3단계를 한 번에 반영했다. 설계에서 달라진 부분만 적는다.

1. **mtime 비교 → 무조건 재읽기**
   계획은 "저장 직전 mtime 을 비교해 바뀌었으면 재로딩" 이었으나, `commit_store()` 가 *항상*
   디스크 최신본을 다시 읽어 변경을 적용하도록 했다. mtime 비교보다 단순하고 더 강한 보장이라
   `store_mtime()` 은 만들지 않았다.

2. **파일 손상 시 세션 저장분 보호 (`commit_store(..., fallback=)`)**
   손상 파일은 `.bak` 으로 보존되지만, 그 상태로 저장하면 세션에 있던 목록이 빈 파일로
   덮여 사라진다. 그래서 손상이 감지되면 세션 사본을 기준으로 병합하도록 `fallback` 인자를 뒀다.

3. **상위 버전 파일이면 [💾 저장] 버튼 자체를 비활성화**
   `commit_store` 의 쓰기 차단만으로는 눌러 본 뒤에야 실패를 알게 되므로 버튼에서 막았다.

4. **저장되는 것은 원문이 아니라 `validate_sql()` 이 돌려준 정규화 쿼리**
   끝 세미콜론이 제거된, 실제로 실행되는 것과 같은 문자열을 저장한다.

5. **함께 고친 별건 (기존 버그)**
   `app.py` 의 SQL 검증 실패 경로가 `st.session_state.sg_error` 에 문자열을 넣고 있었는데,
   렌더 쪽은 `error.get("code")` 로 dict 를 기대한다. 즉 **잘못된 SQL 로 [실행] 을 누르면
   `AttributeError` 로 화면이 깨지던 상태**였다. 이번에 다른 필드와 같은 dict 형태로 맞췄다.

6. **검증 한계 — 실행 확인은 못 했다**
   개발 머신에 Python 인터프리터가 없어 `py_compile` 조차 돌리지 못했다. 문법/논리는 전 구간
   정독과 괄호 균형 검사로만 확인했으므로, **아래 6장 체크리스트는 대상 서버에서 반드시 실행할 것.**
