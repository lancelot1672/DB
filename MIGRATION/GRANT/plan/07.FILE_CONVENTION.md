# 07. 파일 출력 규약 (공통)

**상태: ✅ 구현 완료** — 두 스크립트 모두 적용

`GRANT/` 의 스크립트가 만들어내는 **모든 파일의 위치·이름·수명 규칙**을 한 곳에 모은다.
새 기능을 추가할 때 파일을 하나라도 만든다면 이 문서의 규칙을 따른다.

## 1. 출력 위치

| 종류 | 경로 | 설명 |
|---|---|---|
| 생성 SQL | `./sql/` (`SQL_OUT_DIR`) | **스크립트 실행 위치 기준 상대경로.** 저장소에 남는 산출물 |
| 로그 | `${BASE_PATH}/log/` (`LOG_DIR`) | 실행 1회 = 로그 1개 |
| 임시 파일 | `${BASE_PATH}/tmp/` (`TMP_DIR`) | 실행 종료 시 삭제 |

- `BASE_PATH` 는 `MIG.env` 에서 로딩한다. env 파일이 없으면 즉시 실패한다.
- 세 디렉토리는 스크립트 시작 시 `mkdir -p` 로 보장한다
  (`01:50`, `02:33`).
- **SQL 만 상대경로**인 점에 주의 — 다른 디렉토리에서 `GRANT/01.GRANT_PRIV.sh` 를
  호출하면 그쪽에 `sql/` 이 생긴다. 스크립트는 `GRANT/` 안에서 실행하는 것을 전제로 한다
  (`MIG.env` 로딩도 `./MIG.env` 상대경로라 동일한 전제).

## 2. 타임스탬프

```bash
YMD=$(date '+%Y%m%d')      # 01:40 , 02:25
HMS=$(date '+%H%M%S')      # 01:41 , 02:26
```

- **스크립트 시작 시점에 한 번만** 잡는다. 한 번의 실행에서 생성된 파일은
  권한별로 여러 개여도 **모두 같은 `{YMD}_{HMS}` 를 공유**한다 → 같은 실행의 산출물끼리 묶인다.
- 로그 파일만 `LOGFILE=` 대입 시점에 `date` 를 다시 호출하므로 초 단위로 어긋날 수 있다
  (`01:56`, `02:42`). 의도된 차이는 아니지만 무해해서 그대로 둔다.

## 3. 파일명 권한 코드

생성 SQL 파일명에는 **그 파일에 담긴 권한을 코드로 붙인다.**
같은 롤/OWNER 를 권한 조합만 바꿔 여러 번 실행해도 파일이 구분된다.

| 권한 | SELECT | INSERT | UPDATE | DELETE |
|---|---|---|---|---|
| 코드 | `S` | `I` | `U` | `D` |

구현: `_priv_code()` — `01.GRANT_PRIV.sh:226-243`

- 선택 순서와 무관하게 **항상 S → I → U → D 순으로 조립**한다.
  같은 권한 집합이면 언제나 같은 코드가 나오도록 하기 위함.
  `"DELETE SELECT INSERT UPDATE"` → `SIUD`
- 공백/콤마 구분, 대소문자 모두 허용 — `"select,update"` → `SU`
- `_choose_privs()` 가 결과를 전역 `PRIV_CODE` 에 담는다
  ([04.COMMON_PRIV_SELECT.md](04.COMMON_PRIV_SELECT.md) 참고).

## 4. 파일명 규칙

모든 생성 SQL 은 **어느 모드가 만들었는지 접두사**로 시작한다.
`./sql/` 에 여러 모드의 산출물이 섞여도 `ls` 하면 생성 주체별로 묶여 보인다.

| 접두사 | 생성 주체 |
|---|---|
| `1_` | Mode 1 (DBM_PRIV_INF INSERT) |
| `2_` | Mode 2 (직접 GRANT + SYNONYM) |
| `3_` | Mode 3 (ROLE 기준) |
| `V_` | `02.VERIFY_GRANT.sh` 검증 보정 |

| 생성 주체 | 파일명 | 개수 |
|---|---|---|
| Mode 1 (INSERT) | `1_{BSN}_{S\|I\|U\|D}_{YMD}_{HMS}.sql` | 선택 권한 수만큼 |
| Mode 2 GRANT | `2_{OWNUSR}_TO_{ROLE}_{CODE}_{YMD}_{HMS}.sql` | 1 |
| Mode 2 SYNONYM | `2_{CONUSR}_SYNONYM_{YMD}_{HMS}.sql` | 1 |
| Mode 3 INSERT | `3_{ROLE}_{S\|I\|U\|D}_{YMD}_{HMS}.sql` | 선택 권한 수만큼 |
| Mode 3 GRANT | `3_{OWNUSR}_TO_{ROLE}_{CODE}_{YMD}_{HMS}.sql` | 1 |
| 검증 보정 | `V_FAIL_{BSN}_{YMD}_{HMS}.sql` | 실패 대상마다 1 |
| 로그 | `GRANT_PRIV_{YMD}_{HMS}.log` / `VERIFY_GRANT_{YMD}_{HMS}.log` | 실행마다 1 |

예시:

```
1_CORE_S_20260811_090000.sql                      <-- Mode 1, 권한별 파일이라 코드가 한 글자
2_DBOWN_TO_RL_CORE_ALL_SIUD_20260811_090000.sql   <-- Mode 2, 한 파일에 4종
3_DBOWN_TO_RL_CORE_RO_SI_20260811_090000.sql      <-- Mode 3 GRANT 방식
V_FAIL_CORE_20260811_102600.sql                   <-- 검증 실패 보정
```

- **권한별로 파일이 갈리는 INSERT 방식은 코드가 한 글자**가 된다.
- **시노님 파일과 검증 보정 파일에는 권한 코드를 붙이지 않는다** — 권한 선택과 무관하다.
  (접두사는 붙는다)
- **로그 파일에는 접두사를 붙이지 않는다.** `LOGFILE` 은 모드를 고르기 전에 확정되고
  (`01:57`), 로그 하나가 실행 전체를 담으므로 특정 모드에 귀속되지 않는다.
  로그는 별도 디렉토리에 스크립트명으로 구분된다.

### 구현

- `01.GRANT_PRIV.sh` 는 전역 `FILE_PREFIX` 를 쓴다 (`01:50` 선언).
  각 모드가 **자기 SQL 을 만들기 전에** 값을 세팅한다 — `01:786`(Mode 1),
  `01:427`(Mode 2), `01:577`(Mode 3).
- `_gen_insert_sql` / `_gen_grant_sql` 은 이 전역을 읽어 파일명을 조립하므로,
  **새 모드를 추가하면 `FILE_PREFIX` 세팅을 잊지 말 것** (빠뜨리면 `_CORE_S_...` 처럼
  접두사 없이 언더스코어로 시작하는 파일이 생긴다).
- `02.VERIFY_GRANT.sh` 는 생성 파일이 한 종류뿐이라 `V_FAIL_` 을 리터럴로 박아 둔다 (`02:353`).

## 5. 파일 내용 후처리

생성 직후 공통으로 거치는 처리. 새 생성기를 만들면 동일하게 적용할 것.

1. **빈 줄 제거** — `sqlplus` spool 결과에 섞이는 공백 줄을 걷어낸다
   ```bash
   egrep -v "^[[:space:]]*$" ${f} > ${f}.tmp ; mv ${f}.tmp ${f}
   ```
2. **INSERT 파일은 마지막 줄에 `COMMIT;`** 을 붙인다.
   `GRANT` / `CREATE SYNONYM` 은 DDL 이라 커밋이 필요 없으므로 붙이지 않는다.
3. **건수 카운트** — `grep -c '^INSERT INTO'` / `'^GRANT'` 로 세어 `_ok` 로 보고하고,
   **0건이면 `_fail` 후 중단**한다 (빈 파일을 실행하지 않기 위함).

## 6. 생성 SQL 실행

```bash
sqlplus -s ${DB_USER}/${DB_PASS} @${f} < /dev/null >> ${LOGFILE}
```

- **`< /dev/null` 필수** — 생성 파일은 `COMMIT;` 로 끝나고 `EXIT` 가 없다.
  EOF 를 먹이지 않으면 `sqlplus` 가 `SQL>` 프롬프트에서 멈춘다.
- 호출 직후 `$?` 를 확인한다.

## 7. 보존 / 삭제

| 대상 | 수명 |
|---|---|
| `./sql/*.sql` | **영구 보존.** 미리보기에서 `N` 으로 취소해도 파일은 남는다 |
| `${BASE_PATH}/log/*.log` | 영구 보존 |
| `${BASE_PATH}/tmp/*_$$.{sql,lst}` | 실행 종료 시 `_cleanup` 이 삭제 |

- **"생성은 하되 실행은 확인 후"** 가 이 스크립트들의 기본 방침이다.
  SQL 을 먼저 만들어 `./sql/` 에 남기고, 미리보기(TOP 3) + `y/N` 를 받은 뒤에만 실행한다.
  취소해도 파일이 남으므로 나중에 손으로 검토·실행할 수 있다.
- 임시 파일은 **반드시 `$$`(PID) 접미사**를 붙인다 — 동시 실행 시 충돌 방지.
- **새 임시 파일을 추가하면 `_cleanup` 목록에 등록**할 것 (`01:81-88`, `02:67`).

현재 사용 중인 임시 파일:

| 스크립트 | 파일 |
|---|---|
| `01.GRANT_PRIV.sh` | `GRANT_PRIV_TGT_$$.{sql,lst}`, `GRANT_PRIV_ALL_$$.lst`, `GRANT_ROLE_$$.lst`, `GRANT_GEN2_$$.sql`, `GRANT_ROLE3_$$.lst`, `GRANT_OWNER3_$$.lst`, `GRANT_GEN3I_$$.sql`, `GRANT_GEN3G_$$.sql` |
| `02.VERIFY_GRANT.sh` | `VERIFY_GRANT_TGT_$$.lst`, `VERIFY_GRANT_ALL_$$.lst`, `VERIFY_GRANT_CNT_$$.lst`, `VERIFY_GRANT_GEN_$$.sql`, `VERIFY_GRANT_MSYN_$$.lst`, `VERIFY_GRANT_MGRT_$$.lst` |

## 8. 로그

- `_out()` 이 터미널과 `${LOGFILE}` 에 **동시 출력**한다.
- `_ok` / `_fail` 은 터미널에만 ANSI 색상을 넣고 **로그 파일에는 색상 없이** 기록한다
  (`01:63-79`, `02:57-65`). 로그를 `grep` 할 때 이스케이프 문자가 걸리지 않게 하기 위함.
- `sqlplus` 의 표준출력은 `>> ${LOGFILE}` 로 흘려보내 터미널을 더럽히지 않는다.

## 9. 자격증명

- `DB_USER` / `DB_PASS` / `BASE_PATH` 는 `MIG.env` 에서만 읽는다. **하드코딩 금지.**
- `MIG.env` 는 gitignore 대상(`*.env`)이다.
- 생성되는 `.sql` 파일에는 자격증명이 들어가지 않는다 (접속은 항상 호출 측 `sqlplus` 인자).
