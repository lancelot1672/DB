# 06. 부여 결과 검증

**상태: 🟡 부분 구현** (Mode 1 기준으로는 완성. Mode 2/3 대응 안 됨)

구현 위치: `02.VERIFY_GRANT.sh`

## 요구사항

### 1. 시노님 생성 검증

`CONUSR` 스키마에 `OWNUSR` 테이블 수만큼 시노님이 있어야 한다.

```SQL
SELECT OWNER, SYNONYM_NAME, TABLE_OWNER, TABLE_NAME FROM DBA_SYNONYMS
 WHERE TABLE_OWNER = '{OWNUSR}';
```

### 2. 권한 부여 검증

`RL_{BSN}_ALL` 에 SELECT / INSERT / UPDATE / DELETE 가 각각 테이블 수만큼 있어야 한다.

```SQL
SELECT GRANTEE, OWNER, TABLE_NAME, PRIVILEGE FROM DBA_TAB_PRIVS
 WHERE GRANTEE = '{GRANTEE}';
```

## 남은 작업

### 1. OWNER 조건 누락 (⬜ — 정확성 문제)

`02:219-221` 의 권한 건수 조회는 `GRANTEE` 만 필터한다.

```sql
SELECT PRIVILEGE || ' ' || COUNT(*) FROM DBA_TAB_PRIVS
 WHERE GRANTEE = '${GRANTEE}'
 GROUP BY PRIVILEGE;
```

반면 기대값 `TAB_CNT` 는 `WHERE OWNER = '${OWNUSR}'` 로 뽑는다 (`02:216`).
**한 롤이 두 개 이상 OWNER 의 테이블 권한을 가지면 실제 건수가 기대값보다 커져
정상인데도 FAIL 로 뜬다.** Mode 3 는 하나의 롤에 여러 OWNER 를 누적해 붙이는
용법을 전제하므로 이 문제에 바로 걸린다.

- 수정: `AND OWNER = '${OWNUSR}'` 추가
- 참고로 누락 객체 추출 쿼리(`02:295`)는 이미 `P.OWNER = '${OWNUSR}'` 를 걸고 있어,
  현재는 **"건수는 mismatch 인데 누락 객체는 0건"** 이라는 혼란스러운 출력
  (`02:320-322` 의 메시지)이 나올 수 있다.

### 2. 선택 권한만 검증 (⬜)

`02:28` 의 `PRIVS="SELECT INSERT UPDATE DELETE"` 가 고정이라,
[04](04.COMMON_PRIV_SELECT.md) 로 `SELECT` 만 부여한 대상도 나머지 3개가
0건이라며 FAIL 로 뜬다.

- 검증 대상 권한을 실행 시 선택하게 한다 (`_multi_select_menu`, 기본 전체).
  → `02.VERIFY_GRANT.sh` 에는 `_multi_select_menu` 가 없으므로 복사 필요
    ([00.COMMON_UI.md](00.COMMON_UI.md) 참고)
- 요약 테이블의 컬럼도 선택 권한만 출력하도록 헤더/포맷을 동적으로 구성
- 보정 SQL(`02:343-353`)도 선택 권한만 생성

### 3. Mode 3 대응 — ROLE / OWNER 직접 지정 검증 (⬜)

현재 검증은 `DBM_USR_INF` 를 유일한 대상 소스로 쓰고 `GRANTEE = RL_{BSN}_ALL` 을
규칙으로 가정한다 (`02:203`). Mode 3 는 임의의 `RL_` 롤 + 임의의 OWNER 조합이라
이 경로로는 검증이 안 된다.

- 검증 모드 선택 추가:
  ```
  1. DBM_USR_INF 기준 (기존)
  2. ROLE + OWNER 직접 지정
  ```
- 2번 선택 시 [03](03.MODE3_ROLE_BASED_GRANT.md) 과 동일한 두 메뉴를 재사용해
  `ROLE` / `OWNUSR` 를 고르고, **시노님 검증(Check 1)은 건너뛴다**
  (Mode 3 가 시노님을 만들지 않으므로).
- 검증 SQL:
  ```SQL
  SELECT PRIVILEGE, COUNT(*)
    FROM DBA_TAB_PRIVS
   WHERE GRANTEE = '{ROLE}' AND OWNER = '{OWNUSR}'
   GROUP BY PRIVILEGE ORDER BY PRIVILEGE;

  SELECT COUNT(*) FROM DBA_TABLES WHERE OWNER = '{OWNUSR}';
  ```
- 보정 SQL 생성 시 **부여 방식에 맞춰야 한다** — INSERT 방식으로 부여했다면
  `INSERT INTO DBADM.DBM_PRIV_INF ...`, GRANT 방식이었다면 `GRANT ...`.
  현재 보정 SQL 은 INSERT 문만 생성한다 (`02:349`).
