# 05. 공통 2 — 적용 방식 선택 (DBM_PRIV_INF INSERT vs 직접 GRANT)

**상태: ✅ 구현 완료** (2026-08-11)

| 함수 | 위치 | 역할 |
|---|---|---|
| `_choose_apply_method()` | `01.GRANT_PRIV.sh:251-270` | `APPLY_MODE` = `INSERT` / `GRANT` |
| `_gen_insert_sql()` | `01:279-345` | 권한별 INSERT 파일 N개 + `COMMIT;` |
| `_gen_grant_sql()` | `01:347-388` | GRANT 문 파일 1개 |

호출부는 Mode 3 (`01:648`) 하나. Mode 1 / Mode 2 는 방식이 고정이라 묻지 않으며,
기존 인라인 생성 로직을 그대로 둬 회귀 위험을 피했다 (아래 "적용 범위" 참고).

아래는 구현 시 기준으로 삼은 원래 요구사항 기록.

---

## 요구사항

권한을 실제로 먹이는 두 경로 중 하나를 고른다.

```
1. INSERT INTO DBADM.DBM_PRIV_INF  (내부 TRIGGER 가 GRANT 수행)
2. Direct GRANT                    (GRANT 문 직접 실행)
```

- 조작: 단일 선택 (`_select_menu`, ↑/↓ + Enter)
- 물어보는 시점: **PRIVILEGE 선택 직후, SQL 생성 직전**
- 어느 쪽이든 **생성된 SQL 은 실행 여부와 무관하게 `./sql/` 에 남긴다**
- 실행 전 미리보기(TOP 3) + `y/N` 확인은 두 방식 공통

## 구현 내용

### 1. `_choose_apply_method()` (✅)

```bash
# ------------------------------------------------------------
# _choose_apply_method : pick how privileges are applied.
#   result : APPLY_MODE = "INSERT" | "GRANT"
#   return : 0 on success, 1 on invalid input
# ------------------------------------------------------------
_choose_apply_method() {
    local AMENU=("1. INSERT INTO DBADM.DBM_PRIV_INF  (trigger performs GRANT)"
                 "2. Direct GRANT                    (execute GRANT statements)")
    _out "  Select apply method (Up/Down + Enter):\n"
    if _select_menu "${AMENU[@]}" ; then
        [[ ${MENU_INDEX} -eq 0 ]] && APPLY_MODE="INSERT" || APPLY_MODE="GRANT"
    else
        local _i
        for _i in "${!AMENU[@]}" ; do _out "    %s\n" "${AMENU[$_i]}"; done
        printf "  Enter apply method [1/2]: "
        read -r _i
        case "$(echo ${_i} | tr -d '[:space:]')" in
            1|"") APPLY_MODE="INSERT" ;;
            2)    APPLY_MODE="GRANT"  ;;
            *)    _fail "Invalid apply method: ${_i}" ; return 1 ;;
        esac
    fi
    _log "Apply method: ${APPLY_MODE}"
    return 0
}
```

### 2. 방식별 SQL 생성기 분리 (✅)

| 함수 | 인자 | 출력 전역변수 |
|---|---|---|
| `_gen_insert_sql` | `OWNER` `GRANTEE` `"PRIV [PRIV ...]"` | `GEN_FILES` (공백 구분), `TOTAL_ROWS` |
| `_gen_grant_sql` | `OWNER` `GRANTEE` `"PRIV, PRIV"` | `GRANT_FILE`, `TOTAL_ROWS` |

파일명은 각 함수가 `${SQL_OUT_DIR}` / 권한 코드 / `${YMD}_${HMS}` 로 직접 조립하므로
호출부에서 경로를 넘기지 않는다 → **[07.FILE_CONVENTION.md](07.FILE_CONVENTION.md)**
두 함수 모두 `sqlplus` 실패 시와 0건일 때 `_fail` 후 `return 1`.

생성 SQL 형태:

```SQL
-- INSERT 방식
INSERT INTO DBADM.DBM_PRIV_INF (PRIVILEGE, OWNER, OBJECT_NAME, GRANTEE, CREATED)
VALUES ('{PRIV}', '{OWNER}', '{TABLE_NAME}', '{GRANTEE}', SYSDATE);
-- 파일 마지막 줄
COMMIT;

-- GRANT 방식
GRANT {GRANT_PRIV_CSV} ON {OWNUSR}.{TABLE_NAME} TO {GRANTEE};
```

- INSERT 방식은 **권한별로 파일 분리** (기존 Mode 1 규칙 유지)
- GRANT 방식은 한 문장에 권한이 다 들어가므로 **파일 1개**
- 생성 후 공통 후처리: 빈 줄 제거 → 건수 카운트 → 0건이면 `_fail`

### 3. 적용 범위

| 모드 | 방식 선택 표시 여부 |
|---|---|
| Mode 1 | ❌ 안 물어봄 — 정의상 INSERT 고정 |
| Mode 2 | ❌ 안 물어봄 — 정의상 GRANT + SYNONYM 고정 |
| Mode 3 | ✅ 물어봄 |

Mode 1/2 는 최상위 운영 메뉴에서 이미 방식을 고른 셈이라 두 번 묻지 않는다.

**Mode 1/2 의 인라인 생성 로직은 새 함수로 치환하지 않고 그대로 뒀다.** 중복은 남지만
검증되어 돌아가는 코드에 손대지 않는 쪽이 회귀 위험이 낮다고 판단. 정리하려면
`_gen_insert_sql` / `_gen_grant_sql` 로 치환 가능하나, Mode 1 은 BSN 여러 개를
한 파일에 `spool ... append` 로 누적하는 구조라 함수 시그니처 확장이 필요하다.

## 검증 상태

| 항목 | 결과 |
|---|---|
| 비-TTY 폴백: 공백 입력 → `INSERT` | ✅ |
| 비-TTY 폴백: `2` → `GRANT` | ✅ |
| 비-TTY 폴백: 잘못된 값 → `[FAIL]` + rc 1 | ✅ |
| `_gen_insert_sql` 생성 SQL 형태 (stub sqlplus) | ✅ 권한별 파일 + 따옴표 이스케이프 정상 |
| `_gen_grant_sql` 생성 SQL 형태 (stub sqlplus) | ✅ `GRANT SELECT, UPDATE ON DBOWN.<T> TO <ROLE>;` |
| **INSERT 방식 → `DBM_PRIV_INF` 적재 + 트리거 반영** | ⬜ DB 환경에서 확인 필요 |
| **GRANT 방식 → `DBM_PRIV_INF` 무변경, `DBA_TAB_PRIVS` 만 반영** | ⬜ DB 환경에서 확인 필요 |
| **`n` 응답 시 파일만 남고 DB 무변경** | ⬜ DB 환경에서 확인 필요 |

> GRANT 방식은 `DBM_PRIV_INF` 에 이력이 남지 않는다 —
