# 00. 공통 UI / 스크립트 골격

**상태: 🟡 부분 구현**

모든 모드가 공유하는 **화면 조작 헬퍼와 스크립트 골격**.

> 파일 저장 위치·이름·수명 규칙은 이 문서가 아니라
> **[07.FILE_CONVENTION.md](07.FILE_CONVENTION.md)** 에 있다.

## 요구사항

- 목록 선택은 타이핑이 아니라 **↑/↓ 이동 + Enter** 로 한다.
- 다중 선택은 **↑/↓ 이동 + SPACE 토글 + Enter 확정**, 기본값은 전체 체크.
- 비-TTY(파이프/리다이렉션) 환경에서는 목록을 그대로 출력하고 타이핑 입력으로 폴백한다.
- 로그는 터미널과 파일에 동시에 남고, 파일에는 ANSI 색상이 들어가지 않는다.

## 구현된 내용

### 1. 긴 목록 페이지 스크롤 (✅ — 두 스크립트 모두)

기존 `_select_menu` 는 전체 항목을 한 번에 그리고 `\033[{n}A` 로 되감는 구조라
**항목 수가 터미널 높이를 넘으면 화면이 깨졌다.**
[Mode 3](03.MODE3_ROLE_BASED_GRANT.md) 의 OWNER 목록
(`SELECT DISTINCT OWNER FROM DBA_TABLES`) 이 수십 개라 이 문제에 직접 걸려 같이 구현했다.

- 표시 행수 `win` = `tput lines` − 4 (`tput` 실패 시 24 가정, 최소 3행)
- `top` 오프셋을 유지하며 `cur` 이 창을 벗어날 때만 이동
- **되감기 행수는 `n` 이 아니라 실제 그린 행수** — `win` + 상태줄 1행(`drawn`)
- 상태줄 `-- 12/57 (PgUp/PgDn) --` 은 **목록이 창보다 길 때만** 출력.
  짧은 목록은 기존과 동일하게 동작한다 (회귀 없음)
- `PgUp`/`PgDn` 한 페이지 이동, `Home`/`End` 처음·끝 이동 추가.
  터미널이 Home/End 를 `ESC[1~`/`ESC[4~` 로 보내는 경우는 매칭되지 않고 무시된다(무해)

### 2. 두 사본 동기화 (✅)

`_select_menu` 는 두 스크립트에 복붙되어 있다. 스크롤을 `01` 에만 넣어 한때 갈라졌으나
**`02.VERIFY_GRANT.sh:79-144` 에도 같은 구현을 반영해 본문이 byte 단위로 동일하다.**
양쪽 함수 주석에 `NOTE: keep this in sync with the copy in ...` 을 달아 두었다.

```bash
# 동기화 확인
for f in 01.GRANT_PRIV.sh 02.VERIFY_GRANT.sh ; do
  sed -n '/^_select_menu() {/,/^}$/p' $f > /tmp/sm_$f.txt ; done
diff /tmp/sm_01.GRANT_PRIV.sh.txt /tmp/sm_02.VERIFY_GRANT.sh.txt
```

## 남은 작업

### 헬퍼 중복 자체는 그대로 (🟡)

동기화는 했지만 **복붙 구조는 남아 있다** — 한쪽만 고치면 또 갈라진다.
저장소 규약상 디렉토리 간 공유 라이브러리는 두지 않지만, **`GRANT/` 내부 공용 파일**
(`GRANT/_common.sh`) 정도는 만들어 두 스크립트가 `source` 하는 편이 낫다.

- `_multi_select_menu` 는 아직 `01` 에만 있다. `02` 에도 필요해지면
  ([06.VERIFY.md](06.VERIFY.md) 의 권한 선택 검증) 사본이 하나 더 늘어난다 —
  그 시점이 `_common.sh` 로 빼기 좋은 타이밍이다.

## 준수 사항 (신규 코드 공통)

- 모든 출력은 `_out`/`_log`/`_ok`/`_fail` 경유
- 파괴적 작업(INSERT / GRANT)은 미리보기 후 `y/N` 확인
- `sqlplus` 호출 후 `$?` / `${PIPESTATUS[0]}` 확인
- 파일 저장·이름·정리 규칙 → [07.FILE_CONVENTION.md](07.FILE_CONVENTION.md)
