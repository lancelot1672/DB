# 03. Mode 3 — ROLE 기준 권한 부여 (신규)

**상태: ✅ 구현 완료** (2026-08-11)

구현 위치: `01.GRANT_PRIV.sh:542-716` (`run_role_mode()`),
운영 메뉴 3번 항목 + 분기는 `01:723-750`.

## 왜 새 모드인가

Mode 2 는 **CONUSR 를 먼저 입력**받아 그 계정에 부여된 롤만 보여준다.
Mode 3 는 반대로 **롤을 먼저 고르고** 그 롤에 어떤 OWNER 의 테이블 권한을 붙일지 고른다.
CONUSR 를 모르거나, 특정 롤에 여러 OWNER 의 권한을 누적해 붙일 때 쓴다.

## 기능 1 — `DBA_ROLE_PRIVS` 에서 `RL_` 롤 조회 (✅)

조회 컬럼은 `GRANTEE`, `GRANTED_ROLE` 두 개.

```SQL
SELECT GRANTEE || ' ' || GRANTED_ROLE
  FROM DBA_ROLE_PRIVS
 WHERE GRANTED_ROLE LIKE 'RL\_%' ESCAPE '\'
 ORDER BY GRANTEE, GRANTED_ROLE;
```

- **`LIKE 'RL%'` 가 아니라 `RL\_%` ESCAPE** — 언더스코어를 리터럴로 처리해
  `RLOG_...` 같은 롤이 섞이지 않게 한다. (Mode 2 는 `RL%` 를 쓰고 있음 — [02](02.MODE2_DIRECT_GRANT_SYNONYM.md) 참고)
- spool 결과 → `${TMP_DIR}/GRANT_ROLE3_$$.lst`, 빈 줄 제거 후 배열 로드
- 0건이면 `_fail "No RL_ role found in DBA_ROLE_PRIVS"` 후 `return 1`
- 화면 표시는 두 컬럼 정렬:
  ```
  GRANTEE=APCON        GRANTED_ROLE=RL_CORE_ALL
  GRANTEE=APCON        GRANTED_ROLE=RL_CORE_RO
  ```
- **단일 선택** (`_select_menu`, ↑/↓ + Enter). 비-TTY 폴백은 목록 출력 후 롤명 타이핑.
- 선택 행에서 **`GRANTED_ROLE` 만** 꺼내 이후 `GRANTEE`(권한을 받을 주체)로 사용한다.
  화면에 같이 보이는 `GRANTEE` 컬럼은 "이 롤이 누구에게 부여돼 있는지" 참고용 정보일 뿐이다.
- 같은 롤이 여러 계정에 부여돼 있으면 행이 중복 표시된다. **의도된 동작**
  (어느 계정이 쓰는 롤인지 보고 고르기 위함). 중복이 거슬리면
  `SELECT DISTINCT GRANTED_ROLE` 로 바꾸는 옵션을 후속 검토.

## 기능 2 — 권한을 부여할 OWNER 선택 (✅)

```SQL
SELECT DISTINCT OWNER FROM DBA_TABLES ORDER BY OWNER ASC;
```

- **단일 선택** (`_select_menu`, ↑/↓ 이동 + Enter). 다중 선택 아님.
- 결과를 `OWNUSR` 로 사용. 대상 테이블은
  `SELECT TABLE_NAME FROM DBA_TABLES WHERE OWNER = '{OWNUSR}' ORDER BY TABLE_NAME`
- ⚠️ **목록이 길다** — `SYS`, `SYSTEM` 등 포함 수십 개. 기존 `_select_menu` 는 전체를
  한 화면에 그려 터미널 높이를 넘으면 화면이 깨졌다.
  → [00.COMMON_UI.md](00.COMMON_UI.md) 의 페이지 스크롤을 같이 구현해 해결했다 (`01:98-166`).
  헤더에 총 개수를 표시한다: `Table OWNER in DBA_TABLES (42 found, Up/Down + Enter):`
- 0건은 사실상 발생하지 않지만 방어적으로 `_fail` 처리.
- **Oracle 유지보수 스키마(`SYS` 등)는 걸러내지 않는다** — 요구사항이
  "DBA_TABLES 에서 OWNER DISTINCT" 이므로 그대로 노출한다.

## 전체 흐름

```
1) 운영 메뉴에서 "3. ROLE 기준 권한 부여" 선택
2) [기능 1] DBA_ROLE_PRIVS 의 RL_ 롤 목록 -> 1개 선택           => ROLE (= GRANTEE)
3) [기능 2] DBA_TABLES 의 DISTINCT OWNER 목록 -> 1개 선택       => OWNUSR
4) [공통 1] PRIVILEGE 다중 선택 (DEFAULT 전부)                  => SEL_PRIVS / GRANT_PRIV_CSV
5) [공통 2] 적용 방식 선택 (DBM_PRIV_INF INSERT / 직접 GRANT)   => APPLY_MODE
6) SQL 파일 생성 -> ./sql/ 에 저장
7) 대상 건수 + 미리보기(TOP 3) 출력 -> y/N 확인
8) y 인 경우에만 sqlplus 실행. n 이면 파일만 남기고 exit 0
```

## 생성 파일 규칙

| 적용 방식 | 파일명 | 내용 |
|---|---|---|
| INSERT | `./sql/3_{ROLE}_{S\|I\|U\|D}_{YMD}_{HMS}.sql` (권한별 1개) | `INSERT INTO DBADM.DBM_PRIV_INF ...` + 마지막 줄 `COMMIT;` |
| GRANT | `./sql/3_{OWNUSR}_TO_{ROLE}_{CODE}_{YMD}_{HMS}.sql` (1개) | `GRANT {CSV} ON {OWNUSR}.{TABLE} TO {ROLE};` |

`{CODE}` 는 선택한 권한의 S/I/U/D 조합. 규칙 전체는
→ **[07.FILE_CONVENTION.md](07.FILE_CONVENTION.md)**

## 범위 밖

- **SYNONYM 은 생성하지 않는다.** CONUSR 를 입력받지 않으므로 시노님을 만들 대상 스키마가 없다.
  시노님이 필요하면 [Mode 2](02.MODE2_DIRECT_GRANT_SYNONYM.md) 를 사용한다.
- 여러 OWNER 를 한 번에 붙이는 기능 (요구사항이 "1개 선택"이므로 제외).

### 구현 중 같이 고친 것

`OP_MODE == 2` 분기가 `_cleanup` 뒤에 `exit $?` 를 호출해 **모드의 종료 코드가 아니라
`_cleanup` 의 종료 코드로 끝나고 있었다.** Mode 2/3 모두 `_RC=$?` 로 먼저 받아두도록 수정
(`01:739-749`). Mode 2 가 실패해도 스크립트가 0 으로 끝나던 문제.
